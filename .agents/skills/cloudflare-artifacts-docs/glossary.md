# Glossary

Alphabetical terms from the 2026-10-30 documentation snapshot. Chapter numbers map to [SKILL.md](SKILL.md).

- **Account base URL** — REST root under `/client/v4/accounts/:account/artifacts`. (Ch 3)
- **Adaptive Groups dataset** — `artifactsEventsAdaptiveGroups`, the GraphQL source for Artifacts operation metrics. (Ch 10)
- **ArtifactFS** — FUSE-based repository working tree with on-demand blob hydration. (Ch 6)
- **Artifacts** — Cloudflare versioned storage exposing repositories through Workers, REST, and Git-compatible interfaces. (Ch 1)
- **ArtifactsRepo** — Disposable binding repository capability returned by `get(name)`. (Ch 2)
- **Baseline** — Reviewed repository used as the starting point for independent forks. (Ch 1, 5)
- **Basic authentication** — Git HTTPS auth with non-empty username and repo token secret as password. (Ch 4)
- **Bearer authentication** — Authorization header carrying a Cloudflare API token for REST or full repo token for Git, depending on interface. (Ch 4)
- **Binding** — Configured Worker runtime capability, such as `env.ARTIFACTS`. (Ch 2)
- **Blob** — Byte object returned by binding content reads; `readFile()` supplies MIME type, `readBlob()` does not. (Ch 2)
- **Blobless startup** — ArtifactFS begins with commits, trees, and refs before file contents hydrate. (Ch 6)
- **Cache inputs** — Dependency-defining files used to decide whether CI can reuse an installed sandbox snapshot. (Ch 7)
- **Cloudflare API token** — Credential for REST control-plane access, with Artifacts Read/Edit permissions. (Ch 3, 4)
- **Commit** — Git object identifying a versioned tree and history relationships. (Ch 2, 6)
- **Control plane** — Repo lifecycle and token management through binding or REST; also exposes content reads. (Ch 1, 3)
- **Cursor** — Continuation value used by namespace/repo listings. (Ch 3)
- **Data plane** — Git interface for repository contents and ref updates. (Ch 1, 4)
- **Disposable capability** — RPC resource that should be scoped with `using`. (Ch 2)
- **Dispatch namespace** — Workers for Platforms destination for User Workers. (Ch 7)
- **Event kind** — Analytics category `action` or `error`; distinct from subscription type. (Ch 10)
- **Event schema version** — `metadata.eventSchemaVersion` in event envelopes. (Ch 8)
- **Event subscription** — Routing of selected repository/lifecycle events to an automation consumer. (Ch 8)
- **Fork** — New independent Artifacts repository initialized from existing Artifacts history. (Ch 5)
- **FUSE** — Host filesystem support required for ArtifactFS mounts. (Ch 6)
- **GB-mo** — Storage billing measure based on averaged daily peak storage across a 30-day period. (Ch 10)
- **Git notes** — Separate refs attaching metadata to commits without changing working-tree files. (Ch 1)
- **Hydration** — Fetching an uncached file blob when needed by a mounted working tree. (Ch 6)
- **Import** — Initialize an Artifacts repository from a supported public HTTPS Git remote. (Ch 5)
- **isomorphic-git** — JavaScript Git implementation used by the example to create and push commits from Workers. (Ch 6)
- **Jurisdiction** — Immutable namespace setting restricting repo data storage and processing to `eu` or `us`. (Ch 9)
- **Namespace** — Container and stable routing boundary grouping repositories. (Ch 1)
- **Plaintext** — Explicit token creation's field containing the secret credential. (Ch 2, 4)
- **Read-only repository** — Repo configured to restrict mutations; distinct from a token's read scope. (Ch 5)
- **Read scope** — Repo token access for clone, fetch, and pull. (Ch 4)
- **Ref** — Git branch, tag, or other named reference; APIs may also accept a commit ID. (Ch 2, 8)
- **Remote** — API-returned HTTPS URL for Git access to a repository. (Ch 1, 4)
- **Repository** — Isolated Git service with its own history, refs, tokens, lifecycle, and durable state. (Ch 1)
- **Repository ID** — Opaque API identity distinct from namespace and repo name. (Ch 1)
- **Repo token** — Expiring repository-scoped Git credential; not a REST API token. (Ch 4)
- **Runner** — Isolated CI sandbox executing a command and producing status, logs, and files. (Ch 7)
- **Sandbox** — Isolated execution environment that may be paired with one repo per session ID. (Ch 6)
- **Snapshot** — Cached sandbox state in the CI guide; distinct from Artifacts' internal durability copies. (Ch 1, 7)
- **TTL** — Token time-to-live in seconds. (Ch 4)
- **V4 envelope** — Cloudflare JSON response with result, success, errors, messages, and optional pagination info. (Ch 3)
- **Workflow instance** — Individual run of a Workflow triggered by a change. (Ch 7)
- **Workers Builds** — Managed build/deploy integration for Worker repositories, including preview workflows. (Ch 7)
- **Write scope** — Repo token access including pushes as well as reads. (Ch 4)
